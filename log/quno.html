Quno: An Offline AI on an Arduino UNO Q

Expected outcome

I wanted an Arduino that runs its own AI, with no internet and no cloud. I'd plug it into any computer, open a terminal, and chat with it.

The board is an Arduino UNO Q 4GB, which I named Quno. It has two halves: a small Linux computer and a classic Arduino microcontroller that drives a built-in 13x8 LED matrix. My plan was:

  • Run a language model on the board using Ollama, with Meta's llama3.2:3b model.
  • Chat from the terminal only, with no browser.
  • Connect with just the USB cable, so Wi-Fi isn't needed.
  • Use the LED matrix as a face that shows what the AI is doing.

Where the ideas came from

The starting point was the Arduino Project Hub guide "Build Smarter with Claude Code & Ollama on UNO Q". It showed that the UNO Q can run Ollama, and it paired it with Claude Code as a coding helper.

I took the core idea and changed it as I went:

  • A coding helper, but without Claude Code. I wanted everything offline, so I built my own chat app called Quno, with a coding mode.
  • A "homepage" for the AI. I first pictured a web page, then decided I'd rather do everything in the terminal.
  • The LED matrix was already on the board, so it made sense to use it as a status face.
  • USB-only access came from wanting it to work anywhere, even without Wi-Fi.
  • Robot arm control is a future idea: type to Quno and have it move servos.

How it was built

The first thing I needed to do was to install Ollama and llama3.2:3b onto the board, and it failed straight away because the disk was full, which is strange really as the board was new from the box. As it turns out I had selected the wrong place on the disk, so I cleared out the old files and moved the models onto a bigger partition which sorted it. With the model running, I could use Claude to write the Quno chat app, my personalised version of the local LLM with a chat mode, a coding mode, a model switcher and a speed readout for every reply. I had an idea I wanted to implement where Terminal/PowerShell would open by itself as soon as the board was plugged in, but the board can't pretend to be a keyboard, and Quno needs approval to connect to new computers, so I let that idea go.

Next came the connection. I set up USB networking so the board shows up as a network adapter over the cable at 192.168.7.1. It took me a bit of time to understand the commands needed to access different parts of the board, as this is my first project that has been Linux based. To make it easier, I created a shortcut so that typing ssh quno@192.168.7.1 on any computer drops straight into the Quno "homepage" with a clean screen. Now I had Quno working, I wanted some kind of "thinking" visual from the Arduino, so in Arduino App Lab I built a smiley face for ready, moving dots for thinking and an X for errors, with the chat app switching between them as it works. This is my first Arduino project in a while, and with the new UNO Q board it was tough for me to get my head around there being two sides to the board: half the board is actually a computer, and when I was on my laptop, I was only a keyboard and screen. Using Claude I was able to link my Arduino sketch to Quno, and verified that the link Claude made could effectively implement the sketch I had given him.

What I struggled to understand

What confused meWhat made it click
Which terminal I was typing inI sometimes ran board commands on my Mac and the other way round. Checking the prompt first solved it: arduino@Quno means the board.
What ssh actually doesWhen I connect, my computer is just a screen and keyboard. The AI runs entirely on the board's own hardware.
Why a new computer asks to "Allow accessory"Each computer checks a new USB device once, and ssh checks the board's identity once. After that it's quiet.
The two halves of the boardLinux runs the AI and the chat. The microcontroller runs the sketch that draws the faces. They talk through the Arduino "Bridge".
Why the app needed a Python fileAn App Lab app has a sketch half and a Python half. The Python only had to keep the app alive, which takes 2 lines.
Why the faces vanished after unpluggingAn App Lab app only starts by itself if "Run at startup" is switched on.
Why the faces didn't change during chat at firstI had copied an older version of the chat app onto the board.
The LED code7 means full brightness. A for loop draws a line of pixels, and rows count from 0 at the top.
Offline vs online AIQuno never sends my chats anywhere. An online AI like Claude would need Wi-Fi and an API key, and wouldn't know about my offline chats.

Things I learned

  • Small boards can run real AI, slowly. llama3.2:3b manages about 1.7 tokens (word pieces) per second, so a short answer takes about 40 seconds. It's slow but completely private.
  • Storage matters. AI models are big, and a full disk stops everything. Knowing where space lives on the board saved the project.
  • Linux basics. I learned about logins, services that start at boot, and how to copy files to the board.
  • ssh and USB networking. A USB cable can carry a network connection, which is why ssh works without Wi-Fi.
  • Arduino sketches. I learned how a sketch draws on an LED matrix pixel by pixel, and designed my own error face.
  • How the two halves of the UNO Q talk. Linux sends a message through the Bridge, and the sketch reacts.
  • Security habits. My password got shown in a chat once, so I changed it straight away.

Final outcome

Quno works the way I imagined. I plug the board into any computer, type ssh quno@192.168.7.1, and I'm chatting with an AI that runs entirely on the Arduino, with no internet. The LED matrix smiles when it's ready, shows moving dots while it thinks, and frowns if something goes wrong.
